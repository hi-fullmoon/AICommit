# 大变更分析实施计划

状态：核心链路已实施（2026-09-07）。原始清单保留为设计追踪，交付范围、验证结果及设计调整见文末。

## 目标与边界

保留现有“单次提交 / 批次提交”选择，自动根据输入预算决定一次分析或分块分析。单次模式始终生成一个 commit；批次模式按逻辑变更生成多个 commit。分析块不等于提交组。

小变更保持一次生成请求。大变更不再仅依靠截断正文或把超过 100 个文件的部分归入兜底提交。完整文件归属由本地程序维护，模型只接收受预算约束的内容。

第一版不增加第三种用户模式，不引入磁盘摘要缓存、不自动提交不完整批次计划、不更改现有 split 事务恢复协议。现有实验性 hunk 拆分须保持兼容；无法支持的组合应在请求前明确报错，不静默退化。

## 核心约束

1. 先固定分析范围和快照，再建立全量清单。staged / all 的范围语义保持不变。
2. 每个文件都有稳定 ID；重命名保留旧、新路径。ID 仅在同一快照内稳定。
3. 文件清单覆盖、正文覆盖、摘要质量是不同指标，不将“模型返回了结果”描述成“完整理解”。
4. 默认省略正文的文件仍参与归属、快照校验及现有敏感内容检查。
5. 原始 diff、路径、预览和模型中间摘要均作为不可信数据，继续应用现有信任边界。
6. 任何请求，包括恢复请求、重试、递归汇总和最终生成，都受共享总预算、截止时间和取消信号约束。
7. 分组必须无未知 ID、无遗漏、无重复；文件级和 hunk 级归属不能冲突。
8. 提交前重新校验快照。并发修改、未完成分析或非法分组不能导致静默自动提交。

## 阶段 1：数据契约、配置与基线

- [ ] 定义 `ChangeManifest`：快照标识、范围、文件 ID、路径映射、状态、增删统计、内容类型和正文策略。
- [ ] 定义 `AnalysisChunk`：文件 / 片段 ID、顺序、输入估算及来源指纹。
- [ ] 定义 `AnalysisResult`：有来源引用的事实摘要、关联建议、不确定项、覆盖记录及累计 usage。
- [ ] 定义覆盖状态：`analyzed`、`metadataOnly`、`partial`、`failed`；记录省略或失败原因。
- [ ] 明确“完整”要求：所有需正文分析的片段有有效结果，允许策略指定的 `metadataOnly`，不允许把失败标为策略省略。
- [ ] 增加配置校验、配置展示及示例；制定旧配置迁移说明。
- [ ] 建立小提交请求次数、延迟和模型输入基线。

建议初始配置，最终默认值由阶段 7 的测量确定：

```json
{
  "largeChange": {
    "strategy": "auto",
    "chunkInputTokens": 12000,
    "maxTotalTokens": 200000,
    "concurrency": 2,
    "timeoutMs": 180000
  }
}
```

`strategy` 首版仅支持 `auto`。每次输入还必须服从模型窗口和现有字符上限中更保守的有效限制，并为指令、包装及响应预留空间。旧 `maxFileDiffChars` 用作分块线索，不再直接丢弃剩余正文；`splitMaxPlanFiles` 用作每次规划的文件数量上限，不再决定全局可处理文件数。文档明确这些语义变化。

验收：非法配置在 Git 写操作和 Provider 请求前失败；旧配置可加载；契约能表示重命名、二进制和单文件多片段。

## 阶段 2：有界 Git 读取与快照

依赖：阶段 1。

- [ ] 全量清单优先读取 NUL 分隔的路径、状态和 numstat，正确关联重命名、Unicode、制表符及换行路径。
- [ ] 新增流式内容读取接口，处理子进程错误、背压、取消和退出状态；禁止巨型字符串持续拼接。
- [ ] 流式计算 staged 二进制补丁指纹，保持原有指纹语义；如果确需更改算法，必须显式处理版本兼容。
- [ ] 审计 main、split、快照捕获和验证链路，消除压缩前的全量正文读取，包括未跟踪大文件和二进制变化。
- [ ] 大量路径使用受限批量参数或 Git 支持的路径输入方式，避免 Windows 命令行长度限制；路径按字面值处理。
- [ ] 优先复用现有 split 快照与未跟踪文件保护逻辑，检测读取前后的状态变化。

验收：原始补丁超过 64 MiB 仍能完成读取与指纹计算；正文内存不随补丁总字节数线性增长；空变更和 Git 失败可区分；取消后无遗留子进程；并发修改导致中止。

## 阶段 3：分块调度与分层摘要

依赖：阶段 1、2。建议新增 `src/change-analysis.js`，按复杂度再拆分预算与分块模块。

- [ ] 先省略按策略无需正文的内容，再判断是否适合一次请求；全量清单在本地保留。
- [ ] 优先保持完整文件，超大文件按 hunk 分块，超大 hunk 按行切分；超长单行也必须有界，并记录无法完整分析的情况。
- [ ] 以目录、实现与测试关联改善分块，但不将分块边界固化为提交边界。
- [ ] 使用有界任务队列、背压和共享预算，限制同时驻留的正文与请求数量。
- [ ] 验证模型响应结构及引用 ID；要求每个输入片段有结果或明确不确定状态。
- [ ] 摘要超预算时递归汇总，并设置最大层级 / 请求数量保护，防止不收敛。
- [ ] 保留本地来源映射，父级用候选组 ID 引用子级；禁止在最后一次请求重新发送全部路径。
- [ ] 优先使用可用的模型窗口 / token 计数；未知模型采用保守估算，遇上下文超限缩小失败块后重试。
- [ ] 预留最终生成预算；请求发出前预占预算，并按实际 usage 结算；usage 缺失时保守记账。
- [ ] 接入现有重试与响应恢复，避免外层和内层重试相乘；将退避计入截止时间。
- [ ] 仅在本次运行内缓存已完成块；缓存键包含快照、内容、模型、保护策略和 prompt 版本。

验收：每次请求输入受限；失败只重试对应块；所有调用都被计费记录；预算耗尽后不再发请求；摘要树不遗漏来源；小变更不额外增加一次分析调用。

## 阶段 4：接入单次提交

依赖：阶段 3。

- [ ] 在 `src/main.js` 接入统一分析入口；小变更走直接生成路径，大变更用事实摘要生成一个提交说明。
- [ ] 复用现有语言、commit policy、repository context、敏感内容选择及审阅流程。
- [ ] 重新措辞复用摘要；配置要求重新分析时也服从总预算。
- [ ] 不完整分析仅产生带覆盖提示的草稿，交互审阅后方可提交；非交互模式返回结构化错误，不自动提交。
- [ ] 保留提交前指纹校验与 index 事务语义。

验收：大变更最终仍只有一个 commit；生成内容来源可追溯；分析中断不改写真实 index；快照变化阻止提交；普通小提交请求次数不变。

## 阶段 5：接入批次提交

依赖：阶段 3、4。

- [ ] 用摘要和短 ID 生成局部候选组，再汇总跨块关联；规划请求同样受预算限制。
- [ ] 对存在歧义的跨组关联，允许受预算约束地补充相关摘要或片段。
- [ ] 本地展开组 ID 到文件路径，校验完整覆盖、唯一归属及合法引用，替换超额文件兜底提交。
- [ ] 为最终分组生成消息，复用已有分析；大量分组的消息生成也纳入总预算。
- [ ] 未解决归属显示为待处理项，允许在现有审阅中调整；未解决前不执行、不导出可执行计划。
- [ ] 非交互模式遇不完整分析或非法分组，在自动暂存前失败。
- [ ] 继续生成现有 split plan 工件，由已有 apply / checkpoint / resume 流程执行；内部分析 ID 不改变外部路径语义。
- [ ] 验证实验性 hunk 归属和跨块片段映射；无法处理时给出明确错误。

验收：超过 100 个文件不产生由数量上限导致的兜底组；每个路径或 hunk 完整且唯一分配；跨目录的同一逻辑变更可以合并；plan/apply、hook 失败、resume 和 abort 行为保持兼容。

## 阶段 7：回归、规模验证与交付

交付标准：两个原有模式都能消费统一分析结果；大变更不存在无提示的正文丢弃或文件兜底归组；输入、内存、请求数及时间均有边界；失败不会绕过现有提交保护。

### 设计调整

- Git 内容使用直接写临时文件的方式捕获，Node 按 64 KiB 读取，避免同步 stdout 缓冲上限；没有引入长期运行的异步 Git 子进程。临时文件空间取决于变更大小，Git 捕获有 120 秒命令超时。
- token 计数采用保守估算并结合 Provider 模型窗口。Provider 上下文超限明确失败，尚未实现 tokenizer 精确计数和 Provider 报错后的自动缩块。
- 分析不完整时统一停止，不生成可直接接受的部分草稿。完整分析结果的改写继续使用现有审阅流程。
- 批次分层规划允许合并候选组；无法收敛时要求缩小范围，不把未解决文件自动塞入兜底组。大变更不支持实验性 hunk 规划，单行超过 1 MiB 明确拒绝。
- 未新增真实 Provider 的语义质量基准；本次验证使用模拟 Provider，不能据此保证任意模型的摘要和分组质量。
